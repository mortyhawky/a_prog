# 01 What does portability mean in the context of programming?

```
You write against a specification/interface rather than against the
particular machine underneath it. And there is an important
trade-off: the more you depend on platform-specific details,
the less portable your program becomes—but sometimes that loss of
portability is exactly what you want when you need direct access to 
the hardware or OS.

C is a portable language, which means that C programs 
written on one system can be run on other systems with
little or no modification. 

A1: 
Aperfectly portable program is one whose source code can,
without modification, be compiled to a successful program on a
variety of different computer systems.
```

# 02 Explain the difference between a source code file,
object file, and executable file.

```
A source code file contains the C source code written by the programmer.

An object file contains the machine-code translation of the source code,
along with information needed by the linker, such as symbols and
relocation information. It is not yet a complete executable program.

An executable file is the result of linking one or more object files
with the required startup code and libraries. With static linking,
library code can be included in the executable; with dynamic linking,
the executable instead contains references to shared libraries.

A2:
A source code file contains code as written in whatever language 
the programmer is using. 

Object code files contains machine language code; 
it need not be the code for a complete program. 

An executable file contains the complete code, in
machine language, constituting an executable program.
```

# 04 What does a compiler do?
```
A compiler converts your C code into the instructions 
a computer uses internally.

The compiler is a program that translates the high-level language
program into the detailed set of machine language instructions
the computer requires.
```

# 05 What does a linker do?
```
The C compiler compiles your source code into machine code;
this is called an object file. The linker links your object file(s)
with the object files from libraries you use, resolving references 
between them and producing the executable file.

The compiler and linker use this two-part approach to facilitate
the modularization of programs. Each source file can be compiled
separately into an object file, and the linker then combines the
necessary object files to produce the executable file.
```
